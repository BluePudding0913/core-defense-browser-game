# リリース準備

現在は **PRE-RELEASE（正式リリース前）**。Mavenのバージョンは `1.0.0-SNAPSHOT` とし、完成版の `1.0.0` と区別します。配布物はクライアント・サーバー・マップを同じコミットから揃えます。JARの起動名は引き続き `core-defense-server.jar` です。

## 候補版の確認

専用worktreeのルートで実行します。Node.js 22以上とJDK 17以上が必要です。

```powershell
git rev-parse HEAD
node client/tests/menu-ui.cjs
node client/tests/gameplay-ui.cjs
node client/tests/reconnect-session.cjs
Push-Location server
.\mvnw.cmd clean package
Pop-Location
node client/tests/rooms-server.cjs
```

各コマンドの終了コードと失敗内容を確認し、失敗した候補版は配布しません。変更領域のテストも追加で実行します。ビルドは既存サーバーを停止しない上記の手順を使います。

## プレイ確認と公開前の残項目

以下は実施記録を残してからチェックします。自動テストの成功だけで完了にはしません。

- [ ] PCとスマートフォンの対象OS・ブラウザを決め、実機で描画・操作・音声・横向き表示を確認する。
- [ ] 初回の名前入力と再訪時のメニューで「正式リリース前」が読める。キーボードで開発版の詳細を開閉できる。
- [ ] 通常モードで1人＋CPU、4人、クイックマッチ、合言葉、準備完了、開始、退出、再接続を確認する。
- [ ] 戦闘・購入・建築・ジョブ変更・ダウン／蘇生・勝敗・再プレイを確認する。
- [ ] `?debug=1` の開始時Gold・デバッグ操作を確認する。通常モードの開始条件も別に確認する。
- [ ] 公開環境のTLS・接続元制限・アクセス制限・接続数制限・監視を設計し、[Security policy](../SECURITY.md)の未対応項目を解消する。
- [ ] 静的配信の範囲を限定する。リポジトリ全体を配信するローカル用 `jwebserver` をそのまま公開しない。
- [ ] 素材・効果音・依存ライブラリの配布条件と必要なクレジットを確認する。
- [ ] 公開用の不具合受付先・非公開の脆弱性受付先を用意し、[報告案内](feedback.md)を更新する。
- [ ] 保存データ・ログの扱い、更新時の試合終了、障害時の復旧・旧版への戻し方を決める。
- [ ] 候補コミット、確認端末、テスト結果、既知の不具合、公開判断を記録する。

デバッグモードは開発機能として維持します。現状はURL指定で利用できるため、限定テストの参加者にもその点を伝えます。一般公開時に誰が使えるかは公開範囲に合わせて決定します。

## 正式版へ切り替えるとき

上記を確認したうえで、公開の指示に従って切り替えます。画面の文言変更だけで公開準備完了とはしません。

- `server/pom.xml` のバージョンとリリース記録を更新する。
- `client/menu-ui.js` の開発版案内、`client/menu-ui.css` の対応スタイル、`client/index.html` のタイトル・説明・旧メニュー・JavaScript無効時の文言を更新する。
- READMEの公開状況、対応環境、問い合わせ先、既知の制限を更新する。
- クライアントとサーバーを同時に更新し、旧ブラウザキャッシュも含めて接続確認する。

マージ・タグ作成・公開は、それぞれ指示を受けて行います。
