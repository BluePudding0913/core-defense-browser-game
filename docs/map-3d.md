# 3Dマップの編集

地形は `shared/map.json` の `tileMap.blockMap` で管理する。部屋・通路の名前や床の幅から天井を推定しない。

- `blockSize: 2`：1ブロックは各軸2ワールド単位。従来の1マス（40）は20ブロック。
- 軸：`x` は横、`y` は高さ、`z` は従来の平面マップの `y`。
- `regions`：同じ種類のブロックを直方体でまとめる。
- `from: [x,y,z]` は含む、`to: [x,y,z]` は含まない。座標は整数。
- `kind` は `floor`、`wall`、`ceiling`。いずれも当たり判定を持つ。未指定の空間は空気。

例：列30・行26の天井を高さ130、厚さ6で配置する。

```json
{"kind":"ceiling","from":[600,65,520],"to":[620,68,540]}
```

床の下面・上面も同じ座標で指定する。同じ水平位置に別の高さの床・天井を追加すれば、複数階の地形を定義・描画できる。地上層の床上面は高さ0。既存の部屋は天井130、低い通路は64だが、どの床でも任意のブロック高さに変更できる。隣の天井と段差がある場合、その境界を上まで塞ぐ `wall` の範囲も合わせて調整する。

TIME CONTROLからTRANSIT HALLの区間（列29〜36・行23〜29の床）は高さ130で統一してある。

サーバーとクライアントは同じ3D定義を使う。天井・床支持・身体の接触・FPS射撃を検証する。データはマップ初回配信だけで送信し、毎フレーム送らない。小さいブロックを1個ずつメモリ・描画に展開しないので、上方向を空気で埋める必要はない。

現在の敵経路、施設座標、開放区画は地上層の2Dタイルを併用する。上階を実際に遊べる施設として追加する際には、階段・エレベーターなどの接続、層別の経路・施設・開放管理を追加する。地上層の横方向の配置を変更する場合は `rows` と施設・区画データも更新する。

確認：サーバーの `BlockTerrainTest`、クライアントの `block-terrain.cjs` と `lab3d-models.cjs`。範囲の上下関係、マップ外の座標、地上層の床・天井の欠落は読み込み時に検出する。
