# 敵のカクつきの改善

2026-10-06。調査基点: `6621f20`。

## 原因と修正

画面は100ms周期の敵座標を、各描画フレームで32%ずつ追いかけていた。新しい座標の直後に大きく進み、その後減速するため、一定速度の敵でも速度が脈打つ。描画フレーム数によって追従速度も変わっていた。

敵だけ、受信時刻付きの位置履歴を最大6件保持し、120ms前の時点を線形補間する方式に変更した。通常の100ms通知に20msの揺らぎ余裕を加える。30/60/144fpsで同じ時点の同じ位置を描く。自分の移動予測・入力・ゲーム判定・状態通知周期は変更しない。

敵の表示には約120msの待ちが加わる。通信が大きく遅れた場合には最新の確認位置で止め、壁を越える推測移動はしない。500msを超える空白や160pxを超える位置変更では履歴を作り直す。死亡・部屋変更・再開始では古い敵の履歴を破棄する。

狭い通路対応では、移動先までの全区間を2px刻みで調べていた。経路選択とwander判定の双方で長い区間を繰り返すため、敵数と距離に応じて処理量が増えていた。壁・未解放区域のタイルを部屋ごとにキャッシュし、敵の体の大きさだけ広げた障害物の矩形と移動線分の交差で判定する方式へ置換した。区域解放でキャッシュを更新する。壁への接触は許可し、内側への侵入は拒否する。設備との判定は従来通り別に行う。

## 確認

- サーバーテスト181件成功。既存の狭い通路・角・大型ステップ・目標変更・未解放区域のテストを維持し、200組の区間を0.5px刻みの占有判定と照合した。
- クライアントのローカルテスト全件成功。追加テストでは30/60/144fpsでの等速移動、同じ時刻の二重描画、通知の揺らぎ、通信停止、位置の大変更、部屋変更、再開始、履歴上限を確認した。
- 実サーバーの参加・予約・再接続テストも成功。

Windows/Java 23.0.1/CPU 8、4室（制御室1室、他は各200体）、全区域解放、速度60・ダメージ0の敵、2秒待機後8秒の実WebSocket測定。読み取り停止接続も1本追加した。

| 高負荷室1の更新時間 | 変更前 | 変更後 |
| --- | ---: | ---: |
| p95 | 11.908ms | 3.728ms |
| 最大 | 237.411ms | 111.051ms |

短時間の人工負荷で、初期化やGC、乱数の影響も含む。実ゲームでの体感を保証する測定ではない。敵の描画の改善は上記の時間補間テストで確認した。

再現（server内）:

```powershell
.\mvnw.cmd -o package
.\tools\run-room-load-probe.ps1 -Rooms 4 -Enemies 200 -Seconds 8 -Speed 60 -BaselineRef 6621f20
.\tools\run-room-load-probe.ps1 -Rooms 4 -Enemies 200 -Seconds 8 -Speed 60
```

クライアントの補間確認はルートから`node client/tests/enemy-motion.cjs`。既定のSpeed=0は過去の測定との互換性のため維持しており、動く敵の負荷確認にはSpeedを指定する。
